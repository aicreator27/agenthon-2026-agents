02一個已解除但值得記住的問題

已解除 2026-09-23

T1 的 package 曾是私有，descriptor 卻宣告 public。現已轉公開並用官方方法重驗：匿名 token issued、manifest HTTP 200、11 個 blob 全 206、對遠端 digest 跑官方閘門得 reward 1.0 / 14 passed。

03競賽合約要點

這幾條踩到代價最高：

  • 投稿是一個 zip，不是 image 參照：根目錄只能有 submission.json 與 team-claim.json。
  • image 必須是 linux/amd64、帶 qfbench2.interface_version="2.0"、且可匿名按 digest 拉取。
  • descriptor 恰好 12 個 key，additionalProperties: false。不要加 house_endpoint_only —— 官方自己的 CLI 文件推薦它，而 schema 會直接拒絕。
  • team_id 是從團隊編號與 Team Key 推導的，不是發給你的。descriptor 裡省略它，由 pack 填。
  • 評分環境沒有開放網路。Agent 軌只能走主辦方 House endpoint，沒有任何 vendor API，也沒有機制讓你提供金鑰。
  • 上傳限制：T2 每天 5 次、共 20 次；T1 每天 1 次。被 hold 或 cancel 一樣消耗次數；本地打包與驗證不消耗。

forecast_rationale.md 是必須的，但永遠不計分；g1 只檢查它存在且非空。

04從 fresh clone 到第一次跑分

  1. 先還原 upstream/ —— 不做這步什麼都跑不起來

    upstream/ 刻意不進版控：共用 toolkit 是 CC BY-NC 4.0，vendoring 等於用我們沒有的授權再散布它。它由 sources/SOURCE_REGISTRY.md 的 pin 還原（指令見第 00 節）。

    腳本會 clone 三個官方 repo、checkout 到確切 commit，並驗證 HEAD 而不是相信 checkout。可重複執行，已在 pin 上的不動。

    跳過這步，錯誤會很難懂 —— verifier image 的 Dockerfile 會 COPY upstream/…，所有 smoke、matrix、backtest 都要讀它裡面的官方 units。

  2. build、test、smoke

    .\scripts\build_t2.ps1 ; .\scripts\test_t2.ps1 ; .\scripts\smoke_t2.ps1
.\scripts\build_t1.ps1 ; .\scripts\test_t1.ps1 ; .\scripts\smoke_t1.ps1

    綠燈是：T2 admissible=True labels=[]、T1 reward=1.0 passed=14。看到這個就代表你完整重現了目前狀態，可以開始改東西。這條路實測過：從 GitHub clone 一份全新的跑完整條是通的。

  3. 迭代模型

    T2 的 backtest 拆成兩個容器：模型跑在自己釘死的 stack 上，官方 scorer 跑在 toolkit 的 stack 上。

    Stage A tests/backtests/t2/stage_forecast.py（agenthon-t2:dev）產生樣本 —— 把 tracks/t2_agenthon/src 與 core/src 掛進 PYTHONPATH，就能不重建 image 迭代，那是 20 秒與 3 分鐘的差別。

    Stage B tests/backtests/t2/stage_score.py（verifier image）計算本地 M0、用官方 composite 評分、跑顯著性檢定。

    --configs 把 arm 名稱對應到 EnsembleConfig 覆寫，每個 arm 都對同一批 M0 draws 評分，所以是配對比較。--calibrate 會加上官方 reference CLI 當對照組 —— 改過 harness 之後務必跑它，確認仍落在 1.26 / 1.06 附近。

05打包與上傳前驗證

目前 packaging/t1/ 與 packaging/t2/ 底下沒有可用的 submission.zip。金鑰換過之後，先前打包的兩包已改名為 submission-OLDKEY-DO-NOT-UPLOAD.zip，必須用新金鑰重打包。descriptor 本身不受影響 —— 它不含 team_id，正是為了讓 pack 來填。

打包（每軌一次）

docker run --rm -it -v "<repo>/packaging/t2:/out" \
  --entrypoint qfbench2 agenthon-t2-verifier:dev \
  submission pack --descriptor /out/submission.json \
  --team-number 497 --out /out/submission.zip

T1 同樣一行，換成 packaging/t1 與 T1 的 verifier image。-it 是必要的：Team Key 走隱藏提示輸入，貼上時畫面不會有反應，這正常。

Windows 下 --team-key-file 用不了 —— toolkit 拒絕任何 group/others 可讀的金鑰檔，而 bind mount 給不出 mode 600。隱藏提示是 Windows 上唯一的路，也剛好是最安全的。

上傳前一定要跑的驗證

REPO=aicreator27/agenthon-t2      # 或 agenthon-t1
DIG=sha256:<descriptor 裡的 digest>
TOKEN=$(curl -s "https://ghcr.io/token?scope=repository:$REPO:pull&service=ghcr.io" \
        | python -c 'import json,sys; print(json.load(sys.stdin)["token"])')
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $TOKEN" \
  -H 'Accept: application/vnd.oci.image.manifest.v1+json' \
  "https://ghcr.io/v2/$REPO/manifests/$DIG"

200 是唯一可接受的答案，而「申請匿名 token」那一步正是讓它有意義的關鍵。接著用 scripts/verify_submission_zip.py 驗證壓縮檔。

最後從你們隊伍指定的那一個 CodaBench 帳號上傳。每軌都要用同一個帳號。

06Track 2 現況

純數值模型，不呼叫 House，descriptor 宣告 models: []。現行參數（tracks/t2_agenthon/src/t2_agenthon/forecaster.py 的 EnsembleConfig）：history_window=300、block_length=31、bootstrap_weight=0.80、drift_evidence_c=25.0。

評分是對 M0（官方 text-blind 基準）的比值，所以 1.0 代表「跟一個從來沒讀過文件的預測一樣好」，越低越好。M0 的完整規格在官方 docs/M0-BASELINE.md 第 3 節，本地重建在 tests/backtests/t2/harness.py。

母體v0.1v0.2v0.3贏過 M0
日頻 level（1,168）0.95400.82490.826471.9%
log_return（411）1.16071.03691.021859.6%
月頻 macro（81）1.31971.07560.998455.6%

三個母體都依時間切分、加禁運期，且只開一次。日頻 level 達 p < 0.00005（HAC t = −13.4）。依 roster 組成加權的期望值約 0.863。

怎麼讀這個數字：它是「在公開 roster 組成下大約比 text-blind 基準好 14%」，不是排行榜預測。官方 card 沒有 realized outcome，本地根本算不出真分數；上表用的是從公開面板切出來的代理母體。

為什麼可以相信這個 harness

官方文件記載 shipped reference CLI 對真實 M0 是平均 1.29 / 中位數 1.05。同一支 CLI 跑進這個 harness、在完全不同的資料上量到 1.2573 / 1.0552。harness 一改就要重跑這個對照。

還有一件事要說清楚：我們目前對文本的預測貢獻是零。贏 M0 靠的是同樣資訊下更好的分布模型，不是資訊優勢。

07Track 1 現況

一個通用的 House 迴圈（contract → implement → execute → diagnose → repair → validate），旁邊搭一個確定性的可執行註冊表，目前唯一條目是官方 Black-Scholes exemplar。請求預算適應 4/6/8，操作上限 12，官方上限是每 unit 25。

已驗證：10/10 focused 合約測試；87/87 公開實戰輸出合約，零 crash；官方 exemplar checker reward 1.0、14 tests；釘選版 qfbench2-smoke admissible=True, score=1.0，無 failure label。

產生程式碼的限制：staged 輸入不含 checks/、子行程環境清掉 House 憑證、AST 拒絕網路與行程逃逸、POSIX 資源上限、父行程 non-dumpable、失敗不得提交部分輸出、canary 拒絕。ADR-0005 自己的用詞是「初步容納層，不是強沙箱」—— 請照這個程度理解。

不能宣稱什麼

請務必讀完再對外敘說 T1 的成績。

  • 87/87 是可入場性底線，不是正確率。它證明的是 exit code 與輸出合約，不是 pass@1。
  • 除了 exemplar 之外，沒有任何公開任務拿到 reward 1。
  • 主辦方的 House 路由在本地無法連線，所以實際模型行為完全未測；mock 只固定了傳輸層與狀態機契約。

換句話說：T1 目前證明的是「合法、能跑、不會弄壞格式」，還沒證明「解得開題目」。

08已否決的假設 — 不要重跑

假設結果
對 level target 加 drift（M0 有）否決；零 drift 已是最佳，誤差內
全域縮放離散度（0.90–1.10）否決；1.0 最佳，反過來證明離散度已校準
顯式變異數比例匹配否決；強制 σ√h 反而最差，表示 bootstrap 隱含的期限縮放本身有資訊
對月頻縮短 bootstrap block否決；最佳僅 0.007，block=1 反而差 0.053
改善 log_return a1h21_63 的 joint證明不可改善，見下

最後一項值得展開。variogram_score 讀取預測的方式只透過 mean_k |x_ki − x_kj|^p，在 2-cell 網格上那只是一個純量 —— 所以搜尋空間是一維的，可以窮盡。實測：現行離散度就是最佳點，而且拿「實現值平均」當 oracle（存在的最佳常數預測子）反而更差（1.517 對我們的 1.189）。

原因是結構性的：分數是 VS_ours / VS_M0，而分母在 M0 剛好猜中實現值時趨近 0。貼近 M0 的預測分子會同時趨近 0，比值有界；比 M0 更準的預測不會，它的比值正好在那些 unit 上爆炸。在這個形狀上，metric 獎勵的是靠近 M0，不是準確。

純數值路線的 T2 調參空間已耗盡。variance_ratio、block_length_days、block_min、dispersion_scale、drift_shrink、return_drift_shrink 都還在程式裡，預設關閉，作為否定證據保留。完整證據在 docs/decisions/ 的 ADR-0004 與 ADR-0007。

10迭代鐵律與已付過學費的坑

在 development 上調參，holdout 只開一次。日頻、log_return、月頻三個 holdout 現在都已經開過了 —— 再調參就需要切新的，否則 p 值量的是調參本身而不是模型。規則寫在 ADR-0003。

相依性有兩個方向：時間上的重疊預測窗，以及同一 as-of 的橫向相關。所以顯著性檢定用以 as-of 日期為單位的 moving-block bootstrap，同一日期的 unit 整批一起重樣。對 unit 做 i.i.d. bootstrap 會給出小很多的 p 值。

坑

  • buildx 預設會掛 provenance。本地直接 docker push 會發布一個含 unknown/unknown attestation 的 OCI index。要加 --provenance=false --sbom=false。
  • base image 要用 digest 釘住，否則 CI 重建出來的不是你驗過的那顆。
  • 版本 tag 是 CI 無法做出的宣稱。push 到 main 會重建並把 :v0.3.0 移到那顆重建物上。現在 CI 只打 sha-<commit>，版本 tag 由人在閘門通過後手動打。
  • core/ 是共用的，而兩軌的 publish workflow 都以 core/** 觸發 —— 動它會同時重建並重新 tag 兩軌的 image。
  • PowerShell 5.1 的 Set-Content -Encoding utf8 會寫 BOM，官方 toolkit 的 json.load 會直接拒絕。要用 UTF8Encoding($false)。
  • 不要用 imagetools inspect 證明匿名可拉取 —— 它會用到你已儲存的登入。用第 05 節那個方法。
  • 重構時要保持預設逐位元不變。float64 裡 1.0 - 0.55 不等於 0.45；成對的權重要兩個都明寫。
  • scripts/test_t2.ps1 的搜尋範圍刻意限定 test_t2_*.py：T2 image 只打包 core/ 與 tracks/t2_agenthon/，T1 的合約測試在那裡 import 不到。放寬會跑出兩個假的錯誤。
  • 兩軌在同一個 repo 並行開發，且目前所有人都直接 commit 到 main。動手前先 git log，不要假設工作區是你自己的。
